# Технический стек

**Проект:** Vision-based AI Assistant for Surveillance
**Дата:** 29.10.2026
**Статус:** предварительный. Всё из раздела «Проверить замером» подтверждается на сервере.

---

## 1. Как устроена система

Видео → детектор и трекер → триггеры → короткие клипы → VLM (описание и подтверждение) → журнал событий (Postgres) → агент с инструментами → ответ с временем и клипом.

Две части работают **по очереди**: сначала стадии 1–2 строят журнал, потом агент отвечает по нему. Одновременно на GPU они не запускаются, потому что свободной памяти около 11 ГБ.

## 2. Выбор по компонентам

| Компонент | Основной | Запасной | Менять, если |
|---|---|---|---|
| Детекция | RT-DETRv4-S | RT-DETRv2 через HuggingFace (Apache-2.0) | Экспорт v4 не заводится за полдня, или плохо видит мелких людей (тогда v4-M) |
| Трекинг | ByteTrack | BoT-SORT | Больше одной смены ID на 10 проходов |
| VLM | Qwen3-VL 4B, 4-bit | Qwen3-VL 8B, SmolVLM2 2.2B | Качество описаний низкое |
| Запуск VLM | vLLM | SGLang | Не заводится на сервере. Ollama не подходит: видео для Qwen3-VL там не поддержано |
| Параметры клипа | 2 fps, до 16 кадров, пониженное разрешение | меньше кадров | Нехватка памяти |
| Эмбеддинги | BGE-M3 | multilingual-e5 | Плохо на наших тестах |
| База | PostgreSQL + pgvector | Qdrant | Неудобно или медленно |
| LLM агента | локальная модель 7–9B с tool calling, выбор замером | другая модель | Часто путает инструменты |
| Инструменты агента | 6 готовых функций с проверкой аргументов | свободный SQL | Готовые функции не покрывают вопросы |
| Фреймворк | без фреймворка | Pydantic AI | Нужны сложные сценарии |
| Интерфейс | Streamlit | Gradio | Нужен другой просмотр видео |
| ML-бейзлайн | XGBoost / LightGBM | логистическая регрессия | Мало размеченных примеров |

### Что в таблице не проверено

- Цифры по RT-DETRv4 взяты из ресерча Арай, не перепроверены.
- Кандидат на LLM агента (Qwen3.5-9B) найден по одному обзору, цифры заявлены производителем. Сравнивать с другими моделями только на наших вопросах.
- Размер памяти детектора (1.2–1.5 ГБ) оценочный.
- MCP для MVP не нужен: инструменты работают внутри одного приложения.

## 3. Решения по умолчанию

Если никто не возражает, считаем так:

1. **События (8):** вход, выход, подошёл к зоне, вышел из зоны, пребывание в зоне, взял, положил, оставленный предмет. События 1–5 определяются геометрией, 6–8 подтверждаются VLM. Передача и повторный вход — в расширении.
2. **Язык:** описания в журнале на английском, вопросы на русском и английском. Казахский не включаем.
3. **Эталон:** свои съёмки и MEVA. Склад и КБТУ только как проверка на реальном видео.

## 4. Данные

| Слой | Что | Зачем |
|---|---|---|
| Свои съёмки | 150–300 событий по сценарию, лист событий = эталон | Главные метрики и набор вопросов |
| MEVA | CC-BY-4.0, AWS S3 без регистрации, 37 классов, боксы и треки | Эталон для событий 1, 2, 6, 7, 8 и первый прогон |
| MOT20 | Статичная камера, плотная толпа | Стресс-тест трекера |
| Склад, КБТУ | Реальное видео | Устойчивость и ложные срабатывания |

События 3–5 привязаны к нашим зонам и в публичных датасетах отсутствуют. Метрики по ним считаем только на своих съёмках.

Соответствие нашим событиям классам MEVA:

| Наше событие | Класс MEVA |
|---|---|
| Вход | person enters scene through structure |
| Выход | person exits scene through structure |
| Взял | person picks up object |
| Положил | person puts down object |
| Оставленный предмет | person abandons package |

## 5. Журнал событий

Таблица `events`:

| Поле | Назначение |
|---|---|
| `event_id` | ID события |
| `video_id`, `camera_id` | Источник видео |
| `track_id` | ID человека внутри видео |
| `event_type` | Тип события |
| `t_start`, `t_end` | Время события |
| `zone_id` | Зона |
| `vlm_status` | не проверено / подтверждено / отклонено |
| `vlm_description` | Описание от VLM |
| `keyframe_path` | Ссылка на кадр или клип |
| **`source`** | свои съёмки / MEVA / склад (новое) |
| **`trigger_score`** | уверенность триггера (новое) |
| **`prompt_variant`** | A (без метаданных) или B (с метаданными) (новое) |

Три новых поля нужны, чтобы строить кривую «стоимость против полноты», сравнивать подсказки и считать метрики по слоям данных отдельно.

Дополнительные таблицы: `videos`, `zones`, `tracks`.

## 6. Инструменты агента

Шесть готовых функций. Модель выбирает функцию и заполняет аргументы, SQL пишем мы.

| Инструмент | Назначение |
|---|---|
| `query_events` | Поиск по времени, типу, зоне, камере |
| `count_events` | Подсчёт событий |
| `get_track_timeline` | События одного человека по порядку |
| `search_descriptions` | Поиск по описаниям: текстовый, векторный или гибридный |
| `get_event_details` | Детали события и клип |
| `list_zones_cameras` | Список камер и зон |

`ask_vlm` (повторный анализ клипа) — опционально, из-за затрат.

Правила: точные подсчёты только через базу, аргументы проверяются до выполнения, ответ «не нашёл» обязателен, если подтверждений нет.

## 7. Метрики

| Что | Метрика |
|---|---|
| Детекция событий | precision и recall по типу |
| Стоимость | доля клипов, отправленных в VLM, и GPU-время |
| Главная кривая | recall событий против доли видео, отправленной в VLM: правила против ML-бейзлайна |
| Попадание по времени | R@1 при IoU 0.3, 0.5, 0.7 и mIoU |
| Ответы агента | точное совпадение для чисел и да/нет, допуск для времени, precision/recall для списков |
| Поиск | Recall@k, MRR, время |
| Отрицательные вопросы | доля честных «не нашёл» |
| Подсказка с метаданными | доля выдуманных деталей и полнота описания, вариант A против B |

Разбиение данных: по видео, плюс по актёрам, плюс одна камера только в тесте.

## 8. Научный вклад

1. Кривая «стоимость против полноты» для политики триггеров (правила против ML-модели).
2. Проверка на видео гипотезы, которая для изображений в литературе даёт противоречивые результаты: помогают ли track ID, зона и время в подсказке VLM.

---

## 9. Проверить замером

1. Свободная память GPU1 в разное время суток.
2. Сколько кадров на клип помещается (главный замер).
3. Время на клип при 8 и при 16 кадрах.
4. Помещается ли 8B.
5. Качество описаний: подсказка A против B на одних клипах.
6. Выбор инструментов и аргументов агентом на 30 вопросах.
7. Три режима поиска на одном наборе вопросов.
8. Русский вопрос на английских описаниях: BGE-M3 против multilingual-e5.
9. Лицензии: RT-DETRv4, pgvector, Qdrant, SurveillanceVQA-589K, UCA, UCVL.
